ФУНКЦИОНАЛЬНОЕ ТЕСТИРОВАНИЕ

Выводы
1. Новая функциональность “Личные события” не готова к выпуску
Обоснование: 
Регрессионное тестирование показало, что новая функциональность нарушила работу существующего функционала. Создание уроков полностью заблокировано, обходные пути отсутствуют. Без исправления этого дефекта выпуск новой функции невозможен, так как она встроена в тот же модуль «Расписание»
2. Выпуск всего продукта “Расписание” с новой функциональностью невозможен
Обоснование: 
1. Критический дефект (BR1974-22) делает невозможным создание уроков — ключевую операцию преподавателя.
2. Дефект высокого приоритета (BR1974-20) нарушает бизнес-логику: личное событие перекрывает урок, хотя урок должен отображаться поверх.
3. Остальные дефекты (минорные и мажорные) не являются определяющими, но при наличии критического дефекта продукт не может быть выпущен.
Рекомендации
-  Исправить блокирующий регрессионный дефект — восстановить возможность создания уроков (через иконку «+», слоты, занятые и свободные уроком).
-  Добавить подтверждение удаления личного события** — реализовать модальное окно с текстом: «Вы уверены, что хотите удалить событие \[Название события\]?» 
- Добавить в ТЗ  информацию о том, какие значения допустимы для ввода в поля “Название события”, “Описание” 
- В соответствии с ТЗ,  не допускать создание события длительностью менее 5 минут 
- Исправить  отображение личного события поверх урока 
- Определить, сколько символов допустимо вводить в поле “Описание”, либо убрать маску 0/500, либо зафиксировать ограничение в ТЗ и не допускать ввод 501 символа (устранить противоречие между ТЗ и интерфейсом).
- Определить в ТЗ критерии при создании двух полностью идентичных личных событий (разрешать или блокировать).
- Пересмотреть логику отображения пересекающихся личных событий**  — заменить принцип «позже созданное — выше» на более интуитивный (по времени начала или близости к текущей дате).
- Дополнить ТЗ описанием способа закрытия окна просмотра события (крестик, клик вне окна, клавиша Esc).
- Изменить формулировку требования NFR3** («интуитивно понятный интерфейс») на конкретные, проверяемые критерии 
- После исправлений провести повторное регрессионное тестирование**. Только после этого рассматривать вопрос о выпуске.

API ТЕСТИРОВАНИЕ

Выводы
В ходе тестирования API функциональности «Личные события» было выполнено 15 тест-кейсов (10 позитивных и 5 негативных). Все запросы выполняются в соответствии с документацией и возвращают HTTP 200. В процессе тестирования были выявлены 3 дефекта, связанных с недостаточной валидацией данных на стороне бэкенда: длительность события менее 5 минут, недопустимые цвета, а также эмодзи и спецсимволы в описании. Эти дефекты нарушают требования ТЗ и БТ и требуют доработки. В остальном функциональность работает корректно и соответствует ожиданиям.
По результатам тестирования API функциональности «Личные события» функциональность не может быть сдана в текущем виде.    
Рекомендации
Рекомендуется доработать валидацию на стороне бэкенда для следующих полей:*
- ограничить минимальную длительность события до 5 минут;
- добавить проверку цвета на соответствие предустановленным значениям;
- настроить фильтрацию описания для исключения эмодзи и спецсимволов, если это не предусмотрено требованиями. После доработки рекомендуется провести повторное тестирование для подтверждения исправлений
